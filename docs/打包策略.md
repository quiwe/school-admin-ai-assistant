# 打包策略与避坑指南

> 最后更新：2026-08-17  
> 适用版本：v0.8.0+

---

## 一、触发方式

三个平台均为 **手动触发**（`workflow_dispatch`），在 GitHub Actions 页面或 CLI 执行：

```bash
gh workflow run "Build Android APK" --ref main
gh workflow run "Build Windows Installer" --ref main
gh workflow run "Build macOS App" --ref main
```

所有产物自动发布到同一个 GitHub Release（tag `v{版本号}`），新构建会覆盖旧资产。

**⚠️ 并发控制：** 三个工作流共用同一个并发组 `release-${{ github.ref }}`（`cancel-in-progress: false`）。GitHub 的机制是「同组只保留一个 pending，新的 pending 会取消旧的」。因此**不能同时触发三个工作流**，否则后触发的会取消先触发的 pending 任务，导致该平台漏构建。

**推荐依次触发（等一个完成再触发下一个）：**

```bash
for wf in "Build Android APK" "Build Windows Installer" "Build macOS App"; do
  echo "=== 触发 $wf ==="
  gh workflow run "$wf" --ref main
  sleep 8
  run_id=$(gh run list --workflow="$wf" --limit 1 --json databaseId --jq '.[0].databaseId')
  echo "run_id=$run_id，等待完成..."
  gh run watch "$run_id" --exit-status --interval 20
  echo "$wf 完成"
done
```

三个工作流会自动排队（由于共用并发组），等上一个完成后下一个自动开始。上述脚本通过 `gh run watch` 阻塞等待，确保依次触发不会互相取消。

**版本号来源：**

- `VERSION` 文件 → 所有平台共用，读取后写入安装器版本号和 Release tag。
- `DEVELOPER` 文件 → 发布说明中显示。
- `CHANGELOG.md` → 提取当前版本对应的 `## 版本号 - 日期` 小节作为 Release Notes。

## 二、各平台关键配置

### 🤖 Android APK

Android APK 为**独立运行模式**：APK 内置完整的 Kotlin 后端服务（`AppServer`，监听 `localhost:8765`）和本地 Room 数据库，无需连接桌面端，安装后打开即可使用。前端通过 Capacitor 加载同一套 React 代码，数据全部存储在手机本地。

| 项目 | 值 | 备注 |
|---|---|---|
| AGP | `8.9.2` | Capacitor 8 的 AndroidX 1.17+ 要求 ≥ 8.9.1 |
| Gradle | `8.11.1` | AGP 8.9.2 要求 ≥ 8.11.1 |
| Kotlin | `2.1.0` | |
| KSP | `2.1.0-1.0.29` | Room 编译期注解处理 |
| compileSdk | `36` | Capacitor 8 依赖要求 ≥ 36，**不能降** |
| targetSdk | `36` | |
| minSdk | `26` | Android 8.0+ |
| Java | `21` (Temurin) | Capacitor 8 使用 Java 21 编译 |
| 构建类型 | `assembleDebug` | Debug 签名，无需 keystore |

**CI 关键步骤：**

```yaml
# 1. 前端构建
npm ci && npm run build

# 2. 手动复制 web 资源（不要用 npx cap sync android，会失败）
mkdir -p frontend/android/app/src/main/assets/public
cp -r frontend/dist/* frontend/android/app/src/main/assets/public/

# 3. 生成 Gradle wrapper 并构建
gradle wrapper --gradle-version 8.11.1
./gradlew assembleDebug --no-daemon
```

**Kotlin 编译注意：**
- 使用 `kotlinx.serialization` 时，`ListSerializer` 需要显式 import：`import kotlinx.serialization.builtins.ListSerializer`
- `jsonArrayOf()` 在 1.7.3 版本不存在，用 `buildJsonArray { }` 替代
- `buildJsonArray` 来自 `kotlinx.serialization.json` 包

**依赖兼容性表：**

| Capacitor 版本 | 需要的 AGP | 需要的 Gradle | compileSdk |
|---|---|---|---|
| 8.x | ≥ 8.9.1 | ≥ 8.11.1 | ≥ 36 |

### 🪟 Windows 安装包

| 项目 | 值 | 备注 |
|---|---|---|
| Python | `3.12` | `actions/setup-python@v5` |
| 打包工具 | PyInstaller + Inno Setup 6 | |
| WebView2 | 内置 redist | 离线安装，不依赖网络 |

**⚠️ UPX 必须关闭！**

`packaging/pyinstaller.spec` 中两处 `upx` 都设为 `False`：

```python
# EXE 段
exe = EXE(
    ...
    upx=False,   # ← 必须 False
    ...
)

# COLLECT 段
coll = COLLECT(
    ...
    upx=False,   # ← 必须 False
    ...
)
```

**原因：** UPX 压缩 `python312.dll` 后，Windows 加载器无法正确映射 DLL 到内存，报 `LoadLibrary: 内存位置访问无效`。关闭 UPX 后安装包体积会增大 ~30MB，但稳定性优先。

**其他注意：**
- 默认安装路径 `D:\SchoolAdminAIAssistant`
- 如果用户仍报 DLL 加载失败，先检查 **VC++ 2015-2022 Redistributable** 是否安装

## 三、历史踩坑记录

### ❌ 失败 #1：`checkDebugAarMetadata FAILED`
**原因：** AGP 8.7.3 不满足 Capacitor 8 的 AndroidX 依赖要求  
**修复：** AGP → 8.9.2

### ❌ 失败 #2：`Minimum supported Gradle version is 8.11.1`
**原因：** AGP 8.9.2 需要 Gradle ≥ 8.11.1，wrapper 配置的是 8.7  
**修复：** `gradle-wrapper.properties` 改为 8.11.1，CI 中 `gradle wrapper --gradle-version 8.11.1`

### ❌ 失败 #3：`dependency requires compileSdk 36`
**原因：** Capacitor 8 的 `androidx.activity:1.11.0` 和 `androidx.core:1.17.0` 要求 compileSdk ≥ 36  
**修复：** compileSdk 35 → 36，CI 安装 `platforms;android-36`

### ❌ 失败 #4：`Unresolved reference 'ListSerializer'`
**原因：** `kotlinx.serialization.builtins.ListSerializer` 未 import  
**修复：** 在 FaqRoutes、HistoryRoutes、KnowledgeRoutes 中添加 import

### ❌ 失败 #5：`Unresolved reference 'jsonArrayOf'`
**原因：** `jsonArrayOf()` 在 kotlinx.serialization 1.7.3 中不存在  
**修复：** 替换为 `buildJsonArray { }`

### ❌ 失败 #6（Windows）：`Failed to load Python DLL ... 内存位置访问无效`
**原因：** UPX 压缩了 `python312.dll`  
**修复：** 彻底关闭 UPX（EXE 段 + COLLECT 段都设 `upx=False`）

## 五、快速排查命令

```bash
# 查看工作流列表
gh workflow list --all

# 查看最近运行
gh run list --limit 5

# 查看失败日志
gh run view <run-id> --log-failed

# 重新运行
gh run rerun <run-id>
```
